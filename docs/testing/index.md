# Тестирование

## Стратегия

На машине нет полного Xcode (только CLT) → XCTest и Swift Testing недоступны.
Тесты чистой логики живут в исполняемом таргете `chelka-selftest`
(`make test`), падение проверки — ненулевой exit-код.

Покрытые риски (27 проверок):

- **Коллизии имён при дропе** (`Naming.uniqueName`): перезапись/потеря файла на
  полке. Кейсы: без коллизии, суффикс перед расширением, цепочка `-1/-2/-3`,
  имя без расширения, несколько точек (`.tar.gz`), пробелы и кириллица.
- **Геометрия панели** (`ShelfGeometry`): hit-зона шире чёлки на `hitSlop` с
  каждой стороны, панель прижата к верхней кромке, fallback-полоска по центру
  на экране без чёлки (в т.ч. при нулевом `safeTop`), раскрытая полка не уже
  минимума и по центру экрана. Промах здесь = в полку нельзя попасть курсором.
- **Прогресс анимации** (`expandProgress`/`contentAlpha`): клампинг 0…1,
  контент проявляется во второй половине. Промах = мигание или невидимый контент.

Не покрыто автоматикой (проверяется руками, см. чек-лист):

- AppKit-слой: drag-and-drop, геометрия чёлки, расширение панели — требует
  живого WindowServer и реального drag'а.
- Transport: требует живого пира по ssh.

## Ручной чек-лист MVP

1. `make run` → навести курсор на чёлку → полка раскрывается, «Бросьте файлы сюда».
2. Перетащить файл из Finder на чёлку → файл появился на полке и в `~/Shelf`.
3. Вытащить файл с полки в окно Telegram → становится вложением.
4. С настроенным `peerHost`: после дропа файл появляется в `~/Shelf` на mini,
   на иконке оранжевая → зелёная точка.
5. Выключить Wi-Fi, задропить файл → после 5 попыток красная точка;
   правая кнопка → «Отправить ещё раз» после восстановления сети.
